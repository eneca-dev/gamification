# ИИ-нормоконтроль — демо

Источник данных — индекс Elasticsearch `ai-norms-users-rating`. Ночной VPS-скрипт `sync-ai-norm-checks` переносит события за вчерашний день по Минску в `ai_norm_checks` (upsert по `id`). Пропущенные даты можно загрузить вручную через `--from` и `--to`.

Администратор открывает раздел нормоконтроля внутри `/admin/achievements` и переключает месяцы. Прежний адрес `/admin/norm-control` перенаправляет туда. Раздел показывает число проверок, сотрудников, календарных дней с проверками и дней использования (уникальные пары «сотрудник + день»), виды проверок и активность сотрудников. Один документ может дать несколько событий по разным `mode`, поэтому число проверок не равно числу документов. `mistakes_count` не суммируется и не используется как оценка качества: смысл и масштаб поля различаются по режимам.

На `/achievements` сотрудник видит личную активность за текущий месяц по Минску: число проверок, число уникальных дней и даты проверок. Запрос фильтруется по email вошедшего пользователя. Пустое состояние не утверждает, что человек не пользовался инструментом: оно означает только отсутствие загруженных данных. Блок не является кубком и не обещает начисления.

На этапе демо данные не создают событий геймификации, транзакций и изменений баланса. Запись `ai_norm_check_monthly` в `gamification_event_types` существует, но остаётся неактивной. Размер будущей награды, правило месячного использования и коллекционные достижения будут определены после просмотра данных.

До перехода на актуальный источник в `ai_norm_checks` попали семь строк за май 2026 года из тестового индекса. После сверки с актуальным источником они были удалены. Октябрьские данные этой проблемой не затронуты.
