# Нормоконтроль в достижениях

Источник — Elasticsearch `ai-norms-users-rating`. Ночной VPS-скрипт `sync-ai-norm-checks` переносит события в `ai_norm_checks` с upsert по исходному `id`. По умолчанию он повторно читает семь завершённых дней по Минску, включая вчерашний; для исторической загрузки есть `--from=YYYY-MM-DD --to=YYYY-MM-DD`.

На `/achievements` сотрудник видит число проверок и уникальных дней использования за текущий месяц. Одна проверка за месяц выполняет условие достижения. Администратор видит подробную месячную статистику на `/admin/achievements`.

`ai_norm_check_monthly` настроен на 200 кристаллов, но `is_active=false` и `create_transaction=false`. Синхронизация и показ прогресса не создают событий награждения, транзакций и изменений баланса.

Число проверок — число событий по видам, а не число уникальных документов: один документ может проверяться несколькими способами. `mistakes_count` не используется как оценка качества, потому что смысл поля различается по режимам.
