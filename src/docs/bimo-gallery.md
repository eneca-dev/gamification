# bimo-gallery

Галерея Бимо компании: группировка по отделам и командам, лайки, рейтинг месяца и победитель.

План фичи: `../docs-features/bimo-gallery/plan.md`. Миграция: `supabase/migrations/147_bimo_gallery.sql`.

## Логика работы

Страница `/bimo` доступна авторизованному пользователю при `bimoEnabled()` — тот же флаг,
что у гардероба (`development` или `BIMO_V2_ENABLED=true`). При выключенном флаге страница
отдаёт заглушку «Коллекция ещё не вышла», а пункт «Бимо» в сайдбаре не отображается.

Данные собирает один RPC `fn_bimo_gallery(p_month, p_voter_id)`: активные сотрудники
(кроме команды «Декретный»), их действующий образ, лайки за месяц и признак «я лайкнул».
Образ считается действующим только при выпущенном товаре каталога и живом заказе
`fulfilled` без возврата — та же проверка, что в `getBimoState`, иначе в галерее осталась бы
вещь, потерянная после отмены заказа. Месяц конкурса (`YYYY-MM`) даёт `fn_bimo_month()`
по минскому времени, чтобы границы совпадали у лайков, рейтинга и закрытия месяца.

Лайки: максимум `fn_bimo_like_limit()` = 3 на голосующего в месяц, по одному на Бимо,
себя лайкать нельзя (ограничение таблицы), Бимо без купленного образа — нельзя.
Лимит проверяется в `fn_bimo_like` под advisory-lock по голосующему и дополнительно
триггером `trg_bimo_likes_guard` на вставке: две вкладки и прямой INSERT лимит не обходят.
Повторный лайк того же Бимо не ошибка — функция возвращает текущее состояние, поэтому
двойной клик и повтор запроса безопасны. Снятие лайка освобождает слот; лайки закрытых
месяцев не меняются (`bimo_month_closed`).

Рейтинг месяца считается на клиенте из тех же строк: плотный ранг по числу лайков,
бейджи у первых трёх мест, подиум и строка «ваше место». Фильтры и поиск на ранг не влияют.

Закрытие месяца — `fn_bimo_finalize_month(p_month)` за уже закрытый месяц: победителями
становятся все, кто делит первое место. На каждого пишется событие
`bimo_contest_top1_bonus` (`source = 'bimo'`) с идемпотентным ключом
`bimo_contest_<месяц>_<user_id>`; при `coins > 0` у типа события дополнительно создаётся
транзакция и увеличивается баланс. Повторный вызов ничего не дублирует. Награда по
умолчанию 0 💎 — сумма включается изменением `coins` у типа события, код менять не нужно.
Автоматического запуска пока нет: функция вызывается вручную или будущим кроном.

Отрисовка: карточки используют `BimoThumb` — три слоя `<img>` (фон, портрет костюма,
портретный слой аксессуара) плюс SVG для круглых очков, которые в сцене рисует Canvas.
Геометрия и аффинная правка аксессуара по точкам глаз берутся из `bimoThumbLayers`
в `scenes.ts`, поэтому превью и сцена не расходятся. Canvas (`BimoPortrait`) монтируется
только в двух местах: карточка победителя и модалка по клику — на сотнях карточек
анимированный Canvas недопустим из-за кеша изображений и нагрузки.

Свёрнутая группа не рендерит карточки вообще; внутри группы показывается до 48 Бимо,
дальше кнопка «Показать ещё». По умолчанию раскрыт отдел текущего пользователя.

## Зависимости

- Таблицы: `bimo_likes` (новая), `bimo_equipment`, `bimo_catalog`, `shop_orders`,
  `shop_products`, `ws_users`, `gamification_event_logs`, `gamification_transactions`,
  `gamification_balances`, `gamification_event_types`
- Вью: `view_bimo_contest_winners`
- SQL-функции: `fn_bimo_month`, `fn_bimo_like_limit`, `fn_bimo_gallery`, `fn_bimo_like`,
  `fn_bimo_unlike`, `fn_bimo_finalize_month`, `fn_bimo_likes_guard` (триггер), `fn_minsk_today`
- Тип события: `bimo_contest_top1_bonus` (`coins = 0` до согласования награды)
- Модули: `auth` (`getCurrentUser`), `profile-appearance` (графика через `index.client`),
  `shop` (названия вещей каталога), `cache` (тип `ActionResult`)

## Типы

- `GalleryEntry` — сотрудник + `BimoEquipment` + `likes`/`likedByMe`/`hasLook`
- `GalleryPage` — `month`, `likeLimit`, `usedLikes`, `entries`, `winners`, `lookLabels`
  (`asset_key` → название вещи, чтобы подписи образа не дублировались в коде)
- `GalleryView` — `group` (`dept`/`team`/`none`), `sort` (`likes`/`name`),
  `look` (`custom`/`all`); значения живут в URL
- `BimoThumbLayers` (в `profile-appearance/scenes.ts`) — пути слоёв, CSS-трансформация
  аксессуара и трансформация SVG-очков

## Actions

- `likeBimo({ targetId })` — RPC `fn_bimo_like`. Голосующий берётся из серверной сессии,
  клиентский id не принимается. Revalidate: путь `/bimo`
- `unlikeBimo({ targetId })` — RPC `fn_bimo_unlike`, те же ревалидации

Коды ошибок БД переводятся в тексты: `bimo_likes_exhausted`, `bimo_self_like`,
`bimo_no_look`, `bimo_month_closed`, `bimo_target_inactive`, `bimo_voter_inactive`.

## Queries

- `getGalleryPage(viewerId, winnersLimit = 12)` — страница целиком: галерея, лимит
  лайков, победители и подписи вещей. Без кэша — `liked_by_me` и счётчики должны быть
  свежими после голосования, а остальные три запроса слишком мелкие для кэширования
- `getBimoMonth()` — текущий месяц конкурса из БД

## Ограничения

- Лайк возможен только Бимо с действующим купленным образом; пока коллекция
  не выпущена (`bimo_catalog.is_released = false` у всех) лайкать некого — это ожидаемо
- Фильтр «С образом» включён по умолчанию; при пустом результате страница предлагает
  показать всех и ссылку в гардероб
- У победителя показывается **текущий** образ: образ на момент победы не сохраняется
- Поиск по имени живёт в локальном состоянии, в URL попадают только группировка,
  сортировка и фильтр образов
- `fn_bimo_gallery` возвращает строку на каждого активного сотрудника (559 на 11.2026).
  При приближении к лимиту `db-max-rows` PostgREST (1000) выборку нужно будет страницевать
- Рейтинг и подиум считаются на клиенте из загруженных строк, отдельного запроса нет
- Автозакрытие месяца не настроено: `fn_bimo_finalize_month` вызывается вручную
