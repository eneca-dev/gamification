# Тендерные проекты в достижениях

Ночной VPS-скрипт `sync-ai-tender-usage` читает Elasticsearch и хранит подробные записи в двух таблицах Supabase:

- `ai_tender_advisor_events`: production `app_init` из `ai-tender-advisor-usage`. Пользователь определяется по `user_email`.
- `ai_tender_digest_events`: `tender.view`, `tender.decision`, `tender.create_lead` из `ai-tenderdigest-usage-prod*`. `tender.list` не считается использованием: загрузка списка может происходить при открытии страницы.

Обе таблицы хранят индекс и ID документа Elasticsearch, время события, день по Минску, пользователя, вид действия, время синхронизации и полную исходную запись в `source_data`. Дайджест не содержит email в Elasticsearch. Скрипт сопоставляет полное имя только с единственным активным сотрудником `ws_users`, сохраняет найденный email и статус сопоставления. Несопоставленные и служебные события сохраняются для административной проверки, но не попадают в личный прогресс. Таблицы доступны только серверному ключу.

На `/achievements` Tender Adviser и Tender Digest показывают число событий, уникальных дней и прогресс `0/1` или `1/1`. Один запуск Adviser или одно из трёх учитываемых действий Digest за месяц выполняет условие достижения. На `/admin/achievements` доступны месячные итоги, пользователи, разбивка по действиям и несопоставленные ID.

`ai_tender_advisor_monthly` и `ai_tender_digest_monthly` имеют стоимость 200 кристаллов, но `is_active=false` и `create_transaction=false`. Сейчас собираются только логи и прогресс. Начисление, транзакции и изменение баланса потребуют отдельного включения после сверки данных.
