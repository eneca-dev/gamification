## 0. Предусловия (решить до кода)

1. **Гардероб должен быть выпущен.** Факт на 10.11.2026: в `bimo_catalog` 16 позиций,

## 1. Как это выглядит

Маршрут `/bimo`, пункт в сайдбаре после «Лента компании» (иконка из lucide, например
`PawPrint`). Страница — Server Component, клиентскими остаются только кнопка лайка,
панель управления и модалка.

Логика блоков сверху вниз: сначала итог прошлого месяца (кого чествуем), потом текущая
гонка (за кого бороться), потом инструменты и полный список (где голосовать).

### 1.1 Блоки

| Блок | Что показывает | Поведение |
| --- | --- | --- |
| Хедер | Месяц рейтинга, дней до конца, остаток лайков 3 точками | Остаток обновляется сразу после лайка |
| Победитель месяца | Победитель прошлого месяца: анимированный Бимо, имя, отдел·команда, число лайков, состав образа | Единственный canvas на странице; при нескольких победителях — ряд до 3 карточек |
| Зал славы | Ряд мелких превью победителей прошлых месяцев с подписью месяца | Горизонтальная прокрутка, клик — модалка |
| Подиум | Топ-3 текущего месяца + строка «ваше место» | Пересчитывается из тех же данных, что и список |
| Панель управления | Группировка (отделы / команды / без группировки), сортировка (по лайкам / по имени / случайно), поиск, фильтр «только с образом» | Состояние в URL (`?group=dept&sort=likes&q=…`) — работает «назад» и копирование ссылки |
| Группы | Аккордеон: название, число Бимо, сумма лайков, лидер группы | Раскрыт отдел текущего пользователя, остальные свёрнуты; содержимое монтируется при раскрытии |
| Карточка | Превью 6:5, имя, отдел·команда, кнопка ♥ с числом, бейдж места для топ-3, лента для прошлых победителей, пометка «это вы» | Клик по карточке — модалка с анимированным Бимо, составом образа, числом лайков и местом |

### 1.2 Сетка и адаптив

- Grid: 2 колонки на мобильном, 3 на `sm`, 4 на `lg`, 5 на `xl`, 6 на `2xl`/`3xl`.
- Карточка фиксированной пропорции (6:5 у превью) — без скачков layout при загрузке.
- Проверить 360 / 768 / 1280 / 1920 / `3xl` / `ultrawide`, как в `LayoutShell`.
- Цвета только через `--apex-*`, валюта через `CoinIcon`, `loading.tsx` со скелетоном
  (сетка серых карточек `#E5E7EB` + `animate-pulse`).

## 2. Как это не положить браузер

Ключевое ограничение: `BimoPortrait` — это canvas с собственным кешем изображений
(`MAX_IMAGES = 5`, ~24 МиБ декодированных пикселей, LRU). 559 таких компонентов на
странице недопустимы: кеш начнёт вытесняться на каждой карточке, а анимации съедят CPU.

**Решение — отдельный лёгкий компонент превью `BimoThumb`:** три абсолютно
позиционированных `<img>` в боксе 6:5 — фон, портрет костюма, портретный слой аксессуара.
Никакого canvas, никакой анимации.

- Все образы собираются из **15 статичных файлов** (6 фонов, 5 портретов костюмов,
  3 портрета аксессуаров + «без аксессуара»), поэтому 559 карточек переиспользуют
  один и тот же декодированный набор; браузер кеширует их сам.
- Геометрия повторяет позу покоя из `BimoPortrait`: холст 384×320, портрет занимает
  256×256 с отступом 64 сверху → в CSS это `left: 0; top: 20%; width: 66.67%; height: 80%`.
- Аксессуар при позе покоя смещается аффинным преобразованием по двум точкам глаз
  (`PORTRAIT_EYES` → портретные точки костюма). Для `classic` и `hoodie` это
  тождественное преобразование, для остальных — **константа на костюм, не зависящая
  от кадра**: вычислить один раз и отдать как CSS `transform: matrix(...)`.
- Хелпер считать в `scenes.ts` (`bimoThumbLayers(look)` → три URL + transform), чтобы
  числа якорей не дублировались между canvas и превью (DRY).
- **Круглые очки** растрового файла не имеют: `drawGlasses` рисует их Canvas'ом по двум
  точкам глаз. Для превью нужен один статичный слой — либо отрисовать WebP 512×512
  в стиле остальных аксессуаров, либо повторить геометрию inline SVG (две эллипсовые
  оправы + переносица). Второе предпочтительнее: тот же код геометрии, без новых файлов.
- `loading="lazy"`, `decoding="async"`, обычный `<img>` (файлы статичные и мелкие,
  `next/image` здесь только добавит запросов).

**Анимация — по требованию:** canvas `BimoPortrait` монтируется только в двух местах —
карточка победителя и модалка по клику. Одновременно живых canvas не больше двух.

**Ленивый рендер списка:** свёрнутая группа не рендерит карточки вообще; внутри группы
больше 48 Бимо — кнопка «Показать ещё 24». Виртуализация списка не нужна: при
свёрнутых группах в DOM десятки карточек, а не сотни.

## 3. Данные и серверная логика

### 3.1 Таблицы

```sql
bimo_likes (
  voter_id      uuid not null references ws_users(id),
  target_id     uuid not null references ws_users(id),
  contest_month text not null,          -- 'YYYY-MM' по минскому времени
  created_at    timestamptz not null default now(),
  primary key (voter_id, target_id, contest_month),
  check (voter_id <> target_id)          -- если самолайк запрещён
)
```

Индексы: `(contest_month, target_id)` для рейтинга, `(contest_month, voter_id)` для
подсчёта остатка. Доступ только через функции и `supabaseAdmin`, права у
`anon`/`authenticated` отозвать (образец — `145_revoke_correction_functions_public_access.sql`).

Отдельной таблицы победителей не нужно: в проекте победитель — это **событие**.
`view_contest_monthly_winners` агрегирует `details->>'contest_month'` из
`gamification_event_logs`, но её `winner` — отдел или команда, поэтому для личного
конкурса Бимо завести свой тип события и свою вью, а существующую не ломать.

- Новый тип в `gamification_event_types`: `bimo_contest_top1_bonus`
  (`is_dynamic_coins = false`, `coins` = согласованная награда, `is_active = true`).
- Новая вью `view_bimo_contest_winners`: месяц, user_id, email, число лайков, награда —
  из событий с этим типом (`source = 'bimo'`).

### 3.2 Функции

| Функция | Назначение |
| --- | --- |
| `fn_bimo_gallery(p_month text)` | Одна строка на активного сотрудника: `user_id`, имя, `department_code`, `team`, три слота образа (`outfit`/`accessory`/`background`), `likes`, `liked_by_me`, `has_look`. Join `ws_users` × `bimo_equipment` × агрегат `bimo_likes`. Один запрос вместо N+1 |
| `fn_bimo_like(p_target_id uuid, p_month text)` | Поставить лайк: advisory-lock по голосующему, проверка лимита 3, проверка активности цели, запрет самолайка, запрет лайка Бимо без образа (если так решено) |
| `fn_bimo_unlike(p_target_id uuid, p_month text)` | Снять свой лайк текущего месяца, освободив слот |
| `fn_bimo_finalize_month(p_month text)` | Определить победителя(ей) и записать событие `bimo_contest_top1_bonus` с `details = {contest_month, likes, user_id}`; идемпотентно через `idempotency_key = 'bimo_contest_' || p_month || '_' || user_id` |

Правила, которые обязаны жить в БД, а не в UI:

- Максимум 3 лайка на голосующего за месяц — считать внутри функции под блокировкой,
  плюс триггер `BEFORE INSERT` как вторая линия защиты (две вкладки, повтор запроса).
- Один лайк одному Бимо за месяц — гарантирует первичный ключ.
- Лайки прошлых месяцев не редактируются: функции работают только с текущим месяцем
  (`p_month = to_char(fn_minsk_today(), 'YYYY-MM')`), иначе ошибка `bimo_month_closed`.
- `fn_bimo_finalize_month` вызывается повторно безопасно — идемпотентный ключ не даст
  начислить награду дважды.

### 3.3 Закрытие месяца

Крон 1-го числа — по образцу Edge Function `draw-lottery`: функция вызывает
`fn_bimo_finalize_month` за прошлый месяц. Победитель прошлого месяца после этого
появляется в hero автоматически, рейтинг текущего месяца начинает считаться с нуля
(лайки нового месяца пишутся с новым `contest_month`).

### 3.4 Модуль и кэш

```
src/modules/bimo-gallery/
  actions.ts        # 'use server': likeBimo, unlikeBimo
  queries.ts        # 'server-only': getBimoGallery, getBimoWinners
  types.ts          # Zod + типы строк галереи
  hooks.ts          # через фабрики @/modules/cache
  components/       # BimoGalleryClient, BimoThumb, BimoCard, LikeButton, WinnerHero
  index.ts / index.client.ts
```

- `getBimoGallery` через `cached(..., { tags: ['bimo-gallery'], revalidate: CACHE_5M })`
  из `src/lib/server-cache.ts` — как `getContestWinners`.
- Лайк — Server Action с `ActionResult`, Zod `safeParse`, **обязательным оптимистичным
  обновлением** (счётчик и остаток лайков меняются мгновенно, при ошибке — откат с текстом).
- Ключи кэша добавить в `src/modules/cache/keys/query-keys.ts`:
  `bimoGallery: { all, month(m) }`. Прямой импорт `@tanstack/react-query` запрещён.
- Realtime-подписку на `bimo_likes` не добавлять (YAGNI): цифры обновятся при
  перезагрузке и через 5-минутный кэш. Если заказчик захочет «живой» счётчик —
  добавить таблицу в `src/modules/cache/realtime/config.ts` отдельной задачей.
- Текст ошибок по коду: `bimo_likes_exhausted` → «Лайки на этот месяц закончились»,
  `bimo_self_like` → «Своего Бимо лайкнуть нельзя», `bimo_month_closed` →
  «Месяц уже закрыт», `bimo_no_look` → «У этого Бимо ещё нет образа».

## 5. Чек-лист приёмки

**Функции**

- [ ] Три лайка разным Бимо ставятся, четвёртый отклоняется с понятным текстом.
- [ ] Повторный лайк тому же Бимо в этом месяце невозможен.
- [ ] Снятие лайка освобождает слот; снятие лайка прошлого месяца невозможно.
- [ ] Лайк уволенному/неактивному сотруднику невозможен.
- [ ] Рейтинг и подиум совпадают с `select count(*) from bimo_likes` по месяцу.
- [ ] После закрытия месяца победитель в hero, лайки нового месяца с нуля.
- [ ] Повторный прогон крона не начисляет награду дважды.

**Производительность**

- [ ] Первая отрисовка `/bimo` на 559 сотрудниках: без зависаний, изображений ≤ 15.
- [ ] Прокрутка с раскрытыми 3 группами остаётся плавной.
- [ ] Переключение группировки и сортировки не перезагружает изображения.

**Визуал и UX**

- [ ] Группы, подиум, hero и карточки по Apex UI Kit, без хардкода цветов.
- [ ] Понятно, сколько лайков осталось и что они обнулятся в конце месяца.
- [ ] Пустые состояния: коллекция не выпущена; нет настроенных Бимо; поиск без результатов.
- [ ] Свой Бимо помечен, лайк на себе недоступен (или разрешён — по решению).
- [ ] Скелетон повторяет форму сетки.

## 6. Открытые вопросы к заказчику

1. **Награда победителю.** Рекомендую 💎-награду сопоставимую со стриком-90 (600 💎)
   или вещь из гардероба. Нужна сумма — она попадёт в `gamification_event_types`.
   Награда не должна попасть в метрику «Начислено» как обычный заработок — согласовать
   с правками экономики из `../roulette/tz.md` (этап 4).
2. **Равенство лайков.** Рекомендую объявлять победителями всех, кто делит первое место,
   и награждать каждого. Альтернатива — побеждает тот, кто раньше набрал итоговое число.
3. **Самолайк.** Рекомендую запретить (ограничение `check` в таблице).
4. **Участие Бимо без образа.** Базовый образ уже одет: `outfit.classic` — это Бимо
   в тёмном пиджаке, он бесплатный и не числится в `bimo_catalog`, поэтому отдельно
   «выдавать стартового Бимо» и вставлять строки в `bimo_equipment` не нужно (строка там
   ссылается на выполненный заказ через `source_order_id`, которого у подарка нет).
   «Без образа» здесь означает «ровно дефолт: пиджак, мятный фон, без аксессуара».
   Рекомендую показывать всех, но лайкать только тех, кто что-то купил и надел, и по
   умолчанию включать фильтр «только с образом»: иначе первые недели в галерее будут
   сотни одинаковых базовых Бимо.
5. **Видимость лайков.** Показывать ли, **кто** кого лайкнул, или только счётчики.
   Рекомендую только счётчики — меньше поводов для обид и сговора; сырые данные при
   необходимости смотрит админ в БД.
