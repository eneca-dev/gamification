## Дефекты и ограничения

- Собственный дефект сообщения админского выключателя исправлен ранее и покрыт тестом.
- Ошибки подготовки нового локального baseline/test harness устранены; изменения рабочего SQL для прохождения тестов не понадобились.
- 21 исходная lint-ошибка остаётся открытой. [Список для согласования](lint-approval-scope.md) разделён на A1 (8 сообщений без изменения поведения) и A2 (13 сообщений, связанные со временем/состоянием). Никакие lint-исправления пока не выполнялись.
- V2-FEEDBACK-01 с отсутствующим event_date в транзакциях остаётся статической находкой, без исправления и без живой приёмки.
- Локальный PG18 не является полной копией hosted PG17/Supabase. Auth users — ID-only FK fixture; Auth/PostgREST/Storage и все существующие RLS policies не проверены.
- NULL-source проверен отдельно с ослаблением NOT NULL только внутри локальной откатываемой транзакции. Рабочая схема не менялась.

## Что осталось

1. Полная браузерная/функциональная приёмка v2.0, server cache в живом production-runtime, все размеры экранов и внешние доставки.
2. Отдельное согласование lint A1/A2, затем исправления и проходящий общий lint.
3. Перед первым настоящим ходом — email пользователя, настройка допуска и техническая приёмка. Сам ход пользователь подтвердит в UI.
4. Применение точного SQL в рабочую БД с выключенной рулеткой, публикация и включение — только после отдельных разрешений.
5. Performance baseline и пороги регрессий ещё не согласованы/не измерены; результаты unit/SQL не заменяют benchmark.

Платные проекты не нужны и не создавались. Предыдущий qa-proposal.md — исторический вариант, не текущий план. Коммиты/push, рабочие записи и внешние отправки не выполнялись.
