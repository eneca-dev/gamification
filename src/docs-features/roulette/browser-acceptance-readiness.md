# Браузерная приёмка: доступность сценариев

18.11.2026. Установка SQL в рабочей БД остановлена на BOM/parser error до выполнения первого оператора. Исходные функции и права не изменились. Повторная отправка не выполнялась.

## Окружение сейчас

- localhost:3000 использует рабочий Supabase. Это не изолированный QA, хотя сам Next.js запущен локально.
- Есть отдельный PostgreSQL roulette_qa_exact с безопасной схемой и синтетическими fixtures. Пройденные интеграционные тесты не используют рабочее подключение.
- Этот PostgreSQL не предоставляет сервисы Supabase Auth/PostgREST/Storage. Приложение сейчас обращается к ним через Supabase client, поэтому одного изменения DB URL недостаточно.
- QA_BASE_URL, QA_PROJECT_REF и авторизованная QA_STORAGE_STATE не настроены. Текущий Playwright намеренно запрещает рабочий Supabase project ref. Его ограничения не снимаются.

## Что можно проверить без рабочего аккаунта и БД

Сейчас воспроизводимы SQL-тесты и RTL/jsdom-проверки компонентов. Это уже выполненные проверки, но не браузерная приёмка.

Для браузерной проверки изолированных компонентов подготовлен отдельный локальный test harness, который импортирует настоящие UI-компоненты и подставляет только синтетические ответы серверной границы. Он не содержит рабочих ключей, запрещает внешние запросы и не входит в production routes. Этот QA-механизм согласован и реализован; инструкции и ограничения — в browser-harness.md. Платных ресурсов не требует.

После подготовки такого harness доступны:

- 360/768/1280/1920/2560 px, отсутствие горизонтального переполнения, клавиатура/фокус;
- семь подписей и вероятностей, предупреждение о риске;
- loading/empty/error/disabled/zero balance, impersonation;
- подтверждение/отмена, анимация/reduced motion, результат и восстановление состояния UI;
- свежий баланс и обратный порядок ответов на синтетических данных.

Эти сценарии не доказывают реальную доставку запроса в БД, серверный кэш Next.js или реальную внешнюю интеграцию. Демо/редизайн пользовательского интерфейса этим предложением не подразумевается.

## Для сквозной приёмки ещё нужны

- Полный изолированный Supabase-compatible контур (Auth + PostgREST + нужный Storage), безопасные назначения и отдельная тестовая сессия. Рабочую сессию не переносить.
- Отдельный Next.js production build/runtime с QA-настройками и без рабочих ключей.
- Выделенные synthetic пользователи, QA-only управление временем/секторами, подтверждённое отсутствие внешних фоновых вызовов.
- После этого: catalog/bimo/roulette URL, reload/back/forward, два слоя кэша, потерянный ответ после реального коммита, восстановление того же хода, гонки с покупкой/начислением и все размеры экранов.
- Реальная доставка в тестовые Airtable/Teams требует согласованных тестовых назначений. Заглушки не считаются проверкой доставки.

Платный проект, публикация, включение рабочей рулетки и настоящий ход не разрешены. До подготовки отдельного стенда Playwright на текущий localhost не направляется.
