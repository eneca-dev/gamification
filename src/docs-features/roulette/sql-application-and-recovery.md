## Проверено локально

Отдельная БД roulette_qa_exact, PostgreSQL 18.7, 127.0.0.1:55437, собственный кластер в test-results/local-postgres/data. Без рабочих данных, HTTP/cron/интеграций. Исходная схема — ограниченный проверенный baseline, а не автоматическое применение исторических миграций.

1. Новый baseline и точный SQL 01 установлены с нуля. Зафиксированы определения шести функций и хэш установленного файла.
2. 15 интеграционных тестов: повторы, конкурентные ходы, покупка/начисление в обоих порядках, смена месяца/выключение во время ожидания блокировки, откаты после события/проводки/баланса, права ролей, отсутствие средств и числовые пределы.
3. Семь фиксированных исходов: точные баланс, delta, BYN, повторный результат, исторический и текущий баланс.
4. Четыре отчёта: независимые ожидаемые суммы, границы периода, NULL-source отдельно в откатываемом fixture, SQL/TypeScript, отсутствие потерь/дублирования при join. Полный баланс и списания сохраняются. После восстановления прежних функций все четыре результата снова совпадают с исходными.
5. После удаления QA controls: 70000 вызовов настоящего генератора. Статистический тест дополняет проверку rejection sampling, но не является математическим доказательством равновероятности.
6. SQL 02 выполнен также целым файлом с BEGIN/COMMIT. SQL 05 вернул исходные определения, владельцев, ACL, настройки и режимы безопасности функций.
7. Намеренный сбой после подтверждённого COMMIT SQL 02: cleanup восстановил определения и metadata. Затем весь обычный прогон повторён успешно.

Доказательства: [результаты](local-db-results.json), [сбой после коммита](local-recovery-failure-results.json).

Это PostgreSQL 18, а не рабочий hosted PostgreSQL 17. Supabase Auth/PostgREST/Storage, полный набор RLS и браузерная приёмка этим прогоном не проверены.

## Порядок после отдельного разрешения

1. Перед записью проверить целевой проект, отсутствие объектов SQL 01 и совпадение четырёх определений с исходными хэшами SQL 02. Снять свежий локальный snapshot pg_get_functiondef, owner, ACL, proconfig, prosecdef. При любом расхождении остановиться; прежний пакет не применять вслепую.
2. Сверить SHA-256 файлов с manifest. Выполнить SQL 01; проверить roulette_settings.enabled = false, RLS/grants и отсутствие тестовых helpers. Не создавать пробный ход.
3. Выполнить SQL 02; проверить определения и сравнить согласованные агрегаты на одной согласованной выборке. Не менять остальные показатели.
4. Сохранить результаты проверки. Рулетка остаётся выключенной. Публикация, допуск аккаунта, включение и первый реальный ход — отдельные действия.

## Восстановление при проблеме

- Ошибка внутри пакета до COMMIT: ROLLBACK этого пакета. SQL 01 и 02 — две отдельные транзакции: неудача 02 не отменяет успешный 01.
- Потерянный ответ после отправки не означает откат. Сначала проверить фактические объекты/хэши, затем решать, нужен ли повтор или восстановление.
- Сначала сохранить/установить enabled = false. По согласованной семантике ранее прошедший проверку ход может завершиться; новые отклоняются, восстановление старого результата остаётся доступным.
- Для проблем отчётов применить SQL 05 в рамках отдельно разрешённой процедуры восстановления. Он принимает только известное исходное или установленное определение; при третьем хэше останавливается. CREATE OR REPLACE сохраняет владельца и права. После выполнения сверить их со свежим preflight snapshot.
- У SQL 01 нет прежних определений: он создаёт новые функции. Безопасная остановка — оставить их выключенными. Не удалять журнал, проводки, балансы, справочник или функции восстановления результатов. Удаление объектов и любые компенсирующие финансовые операции не входят в этот пакет.

SQL 05 предназначен для рассмотрения и последующего согласованного применения, поэтому не содержит привязки только к локальному имени БД. Локальный runner проверяет адрес, порт, каталог данных и роль до любых изменений. Наличие файла само по себе не является разрешением его запускать в рабочей БД.
