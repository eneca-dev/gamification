# SQL-пакет: на согласование, не применён

- `00-qa-marker.review.sql`: только новый QA; точный ref, owner-only marker, оба допуска false. Маркер не проверяет фактический адрес подключения.
- `01-roulette.review.sql`: закрытые clock/RNG helpers, настройка default-off, событие roulette_spin, RPC состояния/хода/восстановления/статистики.
- `02-reporting.review.sql`: ровно четыре согласованные функции; только заработанные суммы/игроки исключают roulette.
- `reporting-before.sql`: снимок определений, полученный SELECT 17.11.2026, для проверки расхождений; не инструкция отката.
- `03-qa-controls.review.sql`: только QA; воспроизводимые время и сектор, блокировка RNG для проверки выключателя, триггеры ошибок только для fixture-пользователей `qa-roulette-*`. Ещё требуется конкретный approved project ref и защищённый маркер окружения.
- `04-restore-production-helpers.review.sql`: только QA, восстановление production RNG/часов после сценариев.

## Порядок транзакции

Сначала ищется завершённый месячный результат. Затем блокируется строка баланса пользователя и результат проверяется повторно свежим SELECT (`VOLATILE`). После ожидания фиксируется `clock_timestamp()`, проверяются Europe/Minsk, выключатель и подтверждённая сумма. После прохождения выключателя ход может завершиться даже при параллельном выключении.

Проверка всех возможных результатов на int4 и BYN numeric(12,2) выполняется **до** RNG. Курс фиксируется до броска; проводка получает явный BYN по этому курсу, существующий триггер сохраняет явно переданное значение (не NULL). Нельзя проверять предел только выпавшего сектора: повторные ошибки сместят вероятности. При недопустимых суммах/курсе — технический отказ, без события и без расходования хода; это ограничение типов хранения, не новый лимит ставки.

Событие, delta-проводка и баланс меняются одним RPC. Отсутствующая строка баланса — нет средств; её не создаём. Повреждённый сохранённый результат — ошибка целостности без нового броска. Replay возвращает канонический UUID первого запроса, даже если вызывающий UUID другой.

Production не принимает сектор/часы/override через параметры, GUC или таблицу. Семь равных вероятностей: криптографический байт, отбрасывание 252–255, остаток от деления на семь. QA заменяет определения двух закрытых helpers отдельно; клиентские роли доступа к управлению не получают.

## До применения

1. Утвердить конкретный QA-проект и исходный безопасный baseline схемы. Не проигрывать исторические миграции автоматически.
2. Проверить cron, triggers, background HTTP, назначения OAuth/Teams/Airtable/Storage до запуска; повторять после каждого restore/migration.
3. Сверить `pg_get_functiondef` четырёх сигнатур с reporting-before (нормализовать только переводы строк). При drift остановиться и пересобрать diff.
4. Убедиться, что roulette_private/settings/event type ещё не существуют; пакет намеренно останавливается при конфликте, не меняет чужую схему.
5. Отдельно утвердить применение точного SQL; после утверждения оформить новую миграцию CLI с актуальным timestamp, не изменяя старые.
6. Применить в QA, проверить реальные ограничения/FK/grants/триггер BYN. Запустить финансовые, гонковые и rollback-тесты. Без этих прогонов пакет не считается проверенной миграцией.

Не выдаётся разрешение применять пакет в production. Первичное включение отдельно, после отчётных изменений и приёмки. Откат после реальных ходов не удаляет журнал/проводки: сначала выключение, затем отдельно согласованный forward-fix.
