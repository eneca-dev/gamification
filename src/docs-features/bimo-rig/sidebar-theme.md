# Тон и декор фона Бимо в сайдбаре

План составлен 26.11.2026, упрощён после проверки Pragmatic Architect,
развилки закрыты пользователем. Пайплайн: **Quick** (7 файлов, БД не менялась).
Статус: **реализовано**, ждёт осмотра в браузере.

## Цель

Боковое меню подхватывает тон надетого фона Бимо и становится ярче, вокруг Бимо
покачиваются подходящие этому фону эмодзи. Витрина магазина показывает эмодзи
надетого фона вместо зашитого мятного набора.

## Что было

- `Sidebar.tsx` — фон меню плоский `--apex-surface` (#FFFFFF).
- `BimoModelFigure.tsx:37-41` рисует фон вещи картинкой 600×500 внутри SVG
  с растушёвкой кромки по альфе. В белой колонке арка растворялась в белом —
  отсюда ощущение «картинка в белой рамке».
- Витрина уже делала то, что просили для сайдбара: `BimoShop.tsx` — размытая
  `look.backgroundSrc` под вуалью `bimo-band-veil` с маской `bimo-band-fade`
  (`globals.css:392-402`). Механика окрашенной полосы была готова и отлажена.
- `BimoShop.tsx` — зашитый массив `DECOR` из шести эмодзи (🍃 ✨ ☁️ ⭐ 🐚 🌿),
  не зависящий от надетого фона: на пляже и в звёздном вечере те же мятные
  листья. Действующий недочёт витрины, не только задача сайдбара.
- `globals.css:92-100` — восемь токенов `--bimo-tint-*` с реальными значениями,
  не используемых в коде ни разу. Два из них (`peach`, `lavender`) не
  соответствовали ни одному `asset_key`: эти фоны выведены из коллекции.
  Ключи токенов были в kebab, `asset_key` — в snake (`green_courtyard`).
- У фона `art` — ровно `{ image }`. `parseRigArt` (`validate.ts:85-94`)
  отклоняет любой лишний ключ, и его контракт проверяют магазин, галерея,
  покупка и экипировка. Декор в `art` положить нельзя.
- В каталоге пять фонов-черновиков (`beach`, `clouds`, `green_courtyard`,
  `office`, `starry_evening`), все `is_released = false`; бесплатный мятный живёт
  в коде (`rig.ts:3-5`). **Сегодня у всех пользователей мятный тон**, цветные
  фоны проверяются только в development-примерке (`state.preview`).
- У каждого товара фона админ уже задал эмодзи (`shop_products.emoji`:
  🏖️ ☁️ 🌿 🪴 🌙) в поле `BimoAccessoryModal.tsx:231`. Поле приходит
  в `BimoState.items[].emoji` и правится без миграций.

## Решения

1. **Тон всего меню — токен, полоса у Бимо — размытая картинка.** Подложка
   `<aside>` красится токеном `--bimo-tint-<ключ>`: под подписями меню лежит
   управляемый светлый цвет, а не непредсказуемая яркость рисунка. Вокруг Бимо
   полоса из размытой `backgroundSrc` под `bimo-band-veil`, как на витрине: там
   текста нет, зато видны настоящие цвета арки и исчезает белая рамка.
2. **Имя токена совпадает с суффиксом `asset_key`** (`background.green_courtyard`
   → `--bimo-tint-green_courtyard`), поэтому таблицы соответствий в коде нет,
   а неизвестный фон падает на мятный тон средствами CSS. Ключ из каталога
   подставляется в значение CSS только после проверки формата.
3. **Колонки `decor` в БД нет.** Набор символов — эмодзи товара фона
   (`shop_products.emoji`, уже заполняется админом в модалке загрузки фона)
   плюс два нейтральных символа из кода. Новый фон админа получает декор без
   правок кода; HEX в jsonb противоречил бы правилу «все цвета через
   переменные `--apex-*`» и всё равно не отменял бы правку `globals.css`.
4. **Один компонент декора на сайдбар и витрину.** `BimoDecor` получает набор
   символов и вариант раскладки. Зашитый `DECOR` удалён.
5. **Подписи на тоне получили свои чернила.** `--apex-text-secondary` (#6B7280)
   на тоне даёт 4.0:1, `--apex-text-muted` — около 2.0:1. Введены
   `--apex-text-on-tint` (#4B5563) и `--apex-text-on-tint-muted` (#5A6472):
   на самом тёмном из тонов это 5.8:1 и 4.6:1. Второй токен удалён следующим
   планом ([декор сайдбара](./sidebar-decor.md)) вместе с пересчётом тонов
   из самих картинок: на новом звёздном вечере он давал 3.9:1. Карточки баланса и профиля
   переведены на `--apex-surface` и читаются поднятыми над подложкой —
   прежние мятный и серый фоны спорили бы с тоном пляжа и звёздного вечера.
6. **Свёрнутое меню тоже в тоне.** Декор и полоса требуют места и живут
   в блоке Бимо, который Sidebar и так скрывает при `collapsed`.

## Проверки

- `npx tsc --noEmit` — без ошибок.
- `npm run lint` — 0 ошибок, 46 прежних предупреждений, ни одного в затронутых
  файлах.
- `npm run build` — production сборка проходит.
- Контраст подписей меню посчитан по WCAG для самого тёмного тона
  (`--bimo-tint-starry_evening`): `--apex-text-on-tint` 5.8:1,
  `--apex-text-on-tint-muted` 4.6:1. Цифры относятся к прежним значениям
  токенов, действующие пересчитаны в следующем плане.
- Cache Guardian: нарушений правил модуля cache нет. Три наблюдателя делят
  один ключ `queryKeys.bimo.user`, лишнего запроса нет. По его замечаниям
  `refetchOnWindowFocus` выровнен между наблюдателями (иначе обновление по
  фокусу пропадало в свёрнутом меню, где `BimoCompanion` не рендерится),
  а ветка `isError` убрана: сбойный фоновый refetch больше не гасит
  загруженный образ, стандартный показывается только при отсутствии данных.
- Известный компромисс: `initialData` страницы `/store` больше не попадает
  в кэш — запись создаёт сайдбар, который рендерится раньше. Витрина по-прежнему
  рисуется из серверного пропса, но на жёсткой загрузке появляется один вызов
  `getBimoStateAction`, а тон до ответа мятный. Серверная выдача экипировки
  в layout отклонена: это полный запрос каталога на каждой странице.
  Мёртвую опцию `initialData` у витрины убрал следующий план
  ([декор сайдбара](./sidebar-decor.md)), чтобы код не обещал засев, которого нет.

Осталось на ручной осмотр: все шесть фонов в development-примерке, мобильный
drawer, свёрнутое меню, пользователь без ws user ID, ошибка загрузки экипировки,
reduced motion.

- [x] Сайдбар окрашен в тон надетого фона Бимо; белой рамки вокруг арки нет

- [x] Новый фон, загруженный админом, получает декор без правок кода
- [x] Подписи меню сохраняют контраст на окрашенной подложке
- [x] `npm run lint` и `npm run build` проходят, документация модулей обновлена
- [ ] Осмотр в браузере по списку выше

## Ограничения

- Выпущенных фонов нет, все записи каталога — черновики: в production до выпуска
  коллекции виден только мятный тон.
- Декор — оформление, не часть образа: он не участвует в покупке, экипировке и
  проверках владения, не попадает в `art` и не влияет на `art_version`.
- Новый фон получает мятный тон, пока в `globals.css` нет его токена: это
  деградация, а не ошибка.
- Чернила подписей меню едины для окрашенной и белой подложки: у пользователя
  без ws user ID меню остаётся белым, а подписи стали чуть темнее прежних.
- Галерея Бимо карточки не красит: там рядом десятки образов с разными фонами,
  общий тон страницы смысла не имеет. Вне объёма.

## Отложено

Колонка `bimo_catalog.decor` с собственным тоном и набором эмодзи, поле в модалке
загрузки фона и `updateBimoDecor` в `admin/actions.ts`. Возвращаться к этому
стоит, когда админка начнёт выпускать фоны без разработчика и форма данных
устоится. Перенести записи из кода в колонку позже дешевле, чем сейчас угадать
схему и менять её вместе с роутом, action и queries.
