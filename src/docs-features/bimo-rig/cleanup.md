# Очистка Бимо перед новой коллекцией

План утверждён пользователем 15.11.2026. Git используется только для чтения.

## Цель и условия

Единая текущая модель формата 4, рабочий импорт двух частей одежды и два
обзорных изображения прежних дизайнов. Текущие пиджак, кремовое худи, голая
база, мятный фон, шесть художественных исходников и действующие инструменты
экспорта и проверки нужны для дальнейшей работы.

При обследовании найдены 16 отключённых записей каталога формата 0 без
заказов, экипировки и лотерейных выдач. В Storage находятся две актуальные
текстуры кремового худи и четыре заменённые текстуры. Перед удалением
связи и точные пути проверяются повторно.

## Утверждённые этапы

1. Сохранить и осмотреть два обзорных изображения старой коллекции в `references/`.
2. Удалить зависимости от старой модели и генератора четырёх поз, обновить проверки.
   Проверить текущую сборку до удаления графики.
3. Удалить старые локальные ресурсы, архив и заменённые исходники по точному списку.
   Сверить контрольные суммы сохраняемых ресурсов.
4. По уточнению пользователя очистка Supabase выполняется пользователем вручную.
   Запрос удаления 16 старых записей и товаров был отклонён. Удаление объектов
   Storage не запускалось. Проверенные кандидаты перечислены ниже.
5. Выполнить TypeScript, ESLint, сборку и проверки модели, импорта, сохранения и
   каталога. Проверить пользовательский путь при доступном браузере, обозначить
   ограничения. Подготовить в чате план наполнения магазина.

## Сохраняемые примеры

- `references/old-clothes.png` содержит классический образ, кремовое худи,
  синий бомбер, коралловую рубашку и лавандовый свитер прежнего Бимо.
- `references/old-accessories-backgrounds.png` содержит очки, наушники, кепку,
  берет, шарф и восемь вариантов фона.

Это художественные референсы. Рабочие текстуры и исходники находятся в
`public/bimo/` и `art/`. Прототип, его экспорт и действующие QA-утилиты используются
для подготовки текущих вещей. Временные результаты проверок создаются в `tmp/rig`.

## Прогресс

- Этап 1 — изображения сохранены, осмотрены. Зафиксированы SHA-256 33 сохраняемых файлов.

  37 проверок импорта, 15 сценариев сохранения, проверки каталога и ESLint.
  После удаления старого API обновлены генерируемые типы Next.js.
  Независимое ревью не обнаружило существенных замечаний.

  33 сохраняемых файлов совпали до и после удаления.
- Этап 4 — передан пользователю для ручного удаления по его уточнению.
- Этап 5 — локальные проверки завершены. Браузерная проверка ограничена
  тайм-аутом подключения, ручные сценарии перечислены ниже.

## Итоговые проверки

- TypeScript после `next typegen` прошёл. Первая попытка обнаружила только
  устаревшую генерируемую ссылку на удалённый API.
- ESLint текущего модуля, клиентского API и сохраняемых скриптов прошёл.
- `verify-prototype` прошёл на 1523 позах и 5647 зеркальных пикселях кистей.
- `verify-uploads` прошёл 37 проверок, включая отклонение старых форматов.
- `verify-save` прошёл 15 сценариев с подставными ответами.
- `verify-catalog` проверил оба читателя, владение, права и стандартный образ
  при отсутствии поддерживаемой вещи. Проверки сохранения и каталога используют
  подмены, реальные покупки и запись экипировки этим не проверялись.
- Повторно выполнены `build-model-v4`, `build-templates`, `render-prototype`.
  Все 33 сохраняемых ресурса и исходника совпали по SHA-256 с состоянием до очистки.
  Осмотрены рендеры текущей голой базы, худи и пиджака с production sampler.
- `npm run build` прошёл вне песочницы. Первый запуск внутри песочницы
  завершился ошибкой запуска дочернего процесса PostCSS в Turbopack.
  В сборке присутствует текущий `/api/admin/bimo-item`.

Подключение к вкладке магазина завершилось тайм-аутом
`Emulation.setFocusEmulationEnabled`. Живой сценарий после очистки не проверен.
Ожидаемые результаты ручной проверки следующие.

1. `/store?tab=bimo` показывает пиджак с пропуском. Три последовательных
   нажатия проигрывают удивление, кристалл и радость, затем цикл повторяется.
2. `/admin/products` → «Добавить в Бимо шоп» показывает голую базу.
   Эталонное худи загружает обе части, посадка проходит проверку.
   Предпросмотр трёх реакций сохраняет цельность одежды.

## Ручная очистка Supabase

На момент проверки 16 старых записей формата 0 отключены, без заказов,
экипировки и лотерейных выдач. В эту группу входят четыре одежды
`outfit.blue_bomber`, `outfit.coral_shirt`, `outfit.hoodie`,
`outfit.lavender_sweater`, пять аксессуаров `accessory.blue_headphones`,
`accessory.coral_scarf`, `accessory.lavender_beret`, `accessory.mint_cap`,
`accessory.round_glasses` и семь фонов `background.beach`, `background.clouds`,
`background.green_courtyard`, `background.lavender`, `background.office`,
`background.peach`, `background.starry_evening`.

Текущий черновик `outfit.kremovoe_hudi` формата 4 использует два файла
`outfit/9c95ab52-b35c-46fa-a105-1abe7e7b6e67/v4/symmetric-669bda4f-9742-44d6-9395-261b5d5854ca/`.
Эта запись, товар и обе текстуры нужны текущему импортеру и примерке.

Четыре заменённых объекта находятся в том же `v4/` под именами `outfit.webp`,
`sleeve.webp` и в подпапке `polish-d513fe72-ea06-47e1-bdd4-2cec92ec8914/`.
При работе со Storage удаление файлов выполняется через его API или интерфейс.

воспроизводят ровно оставленный состав. `verify-garments` прошёл на пяти парах,
проверил зеркальность рукавов и отрисовал 360 поз на шести фонах и трёх
сочетаниях аксессуаров. Живые страницы магазина, галереи и админки
пользователь проверяет отдельно.
