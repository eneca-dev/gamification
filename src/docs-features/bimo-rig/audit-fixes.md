# Диагностика и правки модулей Бимо

Разбор кода 18.11.2026 по запросу пользователя: логика покупки, архитектура,
визуал. Пользователь утвердил все пункты, включая три согласуемых (подтверждение
покупки, защита цены, фиксация `search_path`). Git остаётся за пользователем;
удалённое переносится в `D:\bimo-cleanup-2026-11-17`.

## Что проверено и признано верным

Владение вещью — оплаченный заказ, надетое — отдельная запись `bimo_equipment`
с ключом `(user_id, slot)`. Покупка второй вещи не затрагивает ни прежний заказ,
ни надетое; надевание вытесняет вещь только из показа. Двойное списание исключено
блокировкой строки товара в `purchase_bimo_item` и проверкой существующего заказа.
Возврат снимает вещь на чтении: `getBimoState` сверяет `source_order_id` с живыми
неотменёнными заказами. Формулы цены в коде и в SQL совпадают.

## Исправлено

Логика:

- Покупка в один клик заменена общим `PurchaseButton` с чеком-подтверждением.
- Цена сверяется на сервере по `current_crystal_rate()` с ценой, которую видел
  покупатель; при расхождении — отказ с просьбой обновить страницу.
- Товар Бимо с обязательным комментарием стало возможно купить: поля
  `comment_required/label/placeholder` доезжают до витрины и в заказ.
- Остаток лайков считается по `bimo_likes` за месяц, а не по видимым карточкам.
- Список галереи больше не живёт в `useState`: источник правды — пропсы,
  мгновенный отклик даёт `useOptimistic`, откат автоматический.
- Покупка и смена образа ревалидируют `/bimo`: образ в галерее не отстаёт.
- Баланс в витрине — живой запрос вместо серверного пропа.
- Надевание вещи оптимистично, с откатом при ошибке.
- Убраны лишние перезагрузки гардероба: `staleTime` вместо нуля,
  без `refetchOnMount: 'always'` в витрине и в сайдбаре.
- `purchase_product(uuid,uuid,text)` получил `SET search_path TO public`
  (парная версия с `p_free` его уже имела). Тело функции не менялось.

Архитектура:

- Экипировка и образ (`BIMO_SLOTS`, `BimoEquipment`, `BimoArtMap`,
  `DEFAULT_EQUIPMENT`, `bimoLook`, `bimoRenderable`) перенесены в `bimo-rig/look.ts`.
  Галерея и админка больше не импортируют `profile-appearance`.
- Псевдоним `parseLayerArt` убран, везде используется `parseRigArt`.
- Компоненты-пустышки `BimoPortrait` и `BimoThumb` удалены, потребители
  используют `BimoStage` и `BimoStill`.
- `PurchaseButton` переехал в `src/components` — его используют два модуля.
- Добавлена общая `src/components/Button.tsx` с вариантами вместо трёх копий
  стилей кнопок. Формы и размеры повторяют действующий магазин.

Визуал:

- Витрина Бимо — полоса во всю ширину области контента, тон берётся из размытого
  фона надетого образа; ширина пересчитывается при сворачивании сайдбара.
- Админская модалка разбита на секции с заголовками, липкими шапкой и подвалом;
  на узком экране примерка идёт перед органами подгонки. Органы проверки движения
  собраны в один блок, добавлены числовые значения посадки.
- Ошибки отделены от успеха: ошибка — красная плашка с `role="alert"`,
  уведомление — нейтральная.
- Тост ошибки лайка получил `role="alert"`.
- Подиум сужается до числа призёров.
- Конфликт `stagger`-класса и инлайнового `animationDelay` убран.
- Чек подтверждения заказа затемняет фон и блокирует прокрутку, закрывается Esc.

- Края фонов растушёваны в модели маской из собственной альфы рисунка:
  сжатие `feMorphology` на 12 съедает тёмную обводку арки, размытие 16
  растворяет кромку. Проверено рендером на светлой и тёмной подложке.
  Фильтр считается в браузере на каждом превью; если галерея с десятками
  карточек станет тяжёлой, растушёвку можно перенести в `prepareLayer`
  и запекать при загрузке, но тогда текущие фоны придётся залить заново.
- `BimoStage` получил `mx-auto`. Без него блок с шириной по умолчанию 180px
  прижимался к левому краю контейнера — в сайдбаре это читалось как смещение
  Бимо влево, и правкой отступов не лечилось.
- Папка `tmp` вынесена из проекта. Приложение из неё ничего не читает, её
  пересоздают `compile-check` и `verify-garments`; в git она не попадает.

## Переезд галереи

Галерея лайков перенесена из отдельной страницы во вкладку ленты компании
`/activity?feed=bimo`: группировки по отделу и команде там те же, а пункт меню
освободился. Старый адрес `/bimo` перенаправляет на вкладку вместе с фильтрами.
На пилюле вкладки показывается остаток лайков месяца — без этого напоминания
голосование теряется на втором уровне. Ревалидация покупки, экипировки, лайка
и админского сохранения графики переведена с `/bimo` на `/activity`.
Из сайдбара убраны пункт «Бимо» и вся связанная проводка `showBimoGallery`.

## База

Переименованы ключи, разошедшиеся с вещами: `outfit.hoodie` → `outfit.cozy_day`,
`outfit.coral_shirt` → `outfit.sand_shirt`, `outfit.lavender_sweater` →
`outfit.green_sweatshirt`, `accessory.lavender_beret` → `accessory.starry_scarf`.
Миграция меняет `bimo_catalog.asset_key` и `shop_products.effect` в одной
транзакции, отказывается работать при наличии экипировки и проверяет инвариант
`effect = 'bimo:' || asset_key`. Переименование было возможно только до первых
продаж: ключ хранится в `bimo_equipment`.

Удалён первый тестовый черновик импортера `outfit.kremovoe_hudi` и его товар —
штатной функцией `delete_shop_product` со всеми её проверками. Выгрузка для
возврата лежит в `db/outfit-kremovoe-hudi.sql` архивной папки.

Итог: 12 записей каталога, 12 товаров, расхождений ключей нет.
