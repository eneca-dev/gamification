# Стрик-бонусы в выходные — VPS «догон milestone»

## Проблема (корень)

Стрик-бонусы (7/30/90) не выдаются в выходные/праздники:
- `compute-gamification.ts` — ранний выход на выходных (строка ~1758: `if (isWeekend && !workday) return {skipped}`), весь шаг пропускается вместе с milestone-логикой.
- `compute-revit-gamification.ts` — не выходит рано, но гейтит начисление по `isWorkingDay` (строка ~414), milestone проверяется только в зелёный рабочий день.

Стрик при этом растёт и в выходные (модель «выходной = +1», считается в effective-view на чтение), но денежный бонус ждёт следующего рабочего дня. Если порог пересечён в Сб/Вс — бонус приходит только в понедельник (или позже). 03.08.2026 руками закрыли backlog из 32 начислений; нужен постоянный фикс.

Дополнительно: у Revit milestone проверяется **только в зелёной ветке** — если человек пересёк порог, но в следующий рабочий день не запустил плагин, бонус ждёт. У WS страховка в красной ветке уже есть, у Revit — нет.

## Что НЕ трогаем (проверено по данным)

- **Достижения** (`fn_ach_snapshot_rankings` / compute-achievements) — уже гоняются **каждый день**, выходные засчитываются в «дни в топе» (снапшоты есть за все Сб/Вс июля). Фикс не нужен.
- **Топы** (матвью) — рефрешатся тем же ежедневным шагом. Фикс не нужен.
- **Пропуск green/red дней в выходные** — правильно (нельзя штрафовать за субботу). Оставляем.

## Решение: отдельный ежедневный шаг «catch-up»

Не гоняем весь compute в выходные. Добавляем лёгкий шаг, работающий **каждый день (вкл. Сб/Вс/праздники)**: читает effective-стрики и идемпотентно доначисляет недостающие milestone + сбрасывает завершённые циклы. Ровно то, что делали руками 03.08 (проверено на 32 начислениях). Попутно закрывает Revit-пробел красной ветки (работает от effective-стрика, независимо от green/red).

**Вариант A (рекомендуется): DB-функция `fn_catch_up_streak_milestones()` + тонкий шаг оркестратора (один RPC).** Переиспользует валидированный SQL, атомарно, минимум TS. (Вариант B — TS-скрипт с дублем логики — не берём.)

### 1. Миграция: `supabase/migrations/093_catch_up_streak_milestones.sql`

```sql
CREATE OR REPLACE FUNCTION public.fn_catch_up_streak_milestones()
RETURNS jsonb
LANGUAGE plpgsql
SECURITY DEFINER
SET search_path TO 'public'
AS $function$
DECLARE
  v_yesterday date := fn_minsk_today() - 1;
  v_awarded int := 0;
  v_reset int := 0;
  r record;
  v_cycles int;
BEGIN
  -- ===== WS 7 и 30 (награда, без сброса; цикл WS = 90) =====
  FOR r IN
    SELECT e.user_id, wu.email, e.current_streak, e.streak_start_date
    FROM ws_user_streaks_effective e
    JOIN ws_users wu ON wu.id = e.user_id AND wu.is_active = true
    WHERE e.streak_start_date IS NOT NULL AND e.current_streak >= 7
  LOOP
    IF r.current_streak >= 7 AND NOT EXISTS (
      SELECT 1 FROM gamification_event_logs g
      WHERE g.user_id=r.user_id AND g.event_type='ws_streak_7' AND g.event_date >= r.streak_start_date
    ) THEN
      PERFORM process_gamification_event(r.user_id, r.email, 'ws_streak_7','ws', v_yesterday, '{}'::jsonb,
        'ws_streak_7_'||r.user_id||'_'||v_yesterday,
        (SELECT coins FROM gamification_event_types WHERE key='ws_streak_7' AND is_active), true);
      v_awarded := v_awarded + 1;
    END IF;
    IF r.current_streak >= 30 AND NOT EXISTS (
      SELECT 1 FROM gamification_event_logs g
      WHERE g.user_id=r.user_id AND g.event_type='ws_streak_30' AND g.event_date >= r.streak_start_date
    ) THEN
      PERFORM process_gamification_event(r.user_id, r.email, 'ws_streak_30','ws', v_yesterday, '{}'::jsonb,
        'ws_streak_30_'||r.user_id||'_'||v_yesterday,
        (SELECT coins FROM gamification_event_types WHERE key='ws_streak_30' AND is_active), true);
      v_awarded := v_awarded + 1;
    END IF;
  END LOOP;

  -- ===== WS 90 (награда + сброс цикла), кроме pending =====
  FOR r IN
    SELECT e.user_id, wu.email, e.current_streak, e.streak_start_date
    FROM ws_user_streaks_effective e
    JOIN ws_users wu ON wu.id = e.user_id AND wu.is_active = true
    WHERE e.streak_start_date IS NOT NULL AND e.current_streak >= 90
      AND (SELECT pending_reset_date FROM ws_user_streaks s WHERE s.user_id=e.user_id) IS NULL
      AND NOT EXISTS (SELECT 1 FROM gamification_event_logs g
        WHERE g.user_id=e.user_id AND g.event_type='ws_streak_90' AND g.event_date >= e.streak_start_date)
  LOOP
    SELECT completed_cycles INTO v_cycles FROM ws_user_streaks WHERE user_id=r.user_id;
    PERFORM process_gamification_event(r.user_id, r.email, 'ws_streak_90','ws', v_yesterday,
      jsonb_build_object('completed_cycles', v_cycles+1),
      'ws_streak_90_'||r.user_id||'_'||v_yesterday,
      (SELECT coins FROM gamification_event_types WHERE key='ws_streak_90' AND is_active), true);
    UPDATE ws_user_streaks SET current_streak=0, streak_start_date=null, completed_cycles=completed_cycles+1,
      pending_reset_date=null, pending_reset_expires_at=null WHERE user_id=r.user_id;
    v_awarded := v_awarded + 1; v_reset := v_reset + 1;
  END LOOP;

  -- ===== Revit 7 (награда). ВАЖНО: до Revit-30, иначе сброс обнулит streak_start_date =====
  FOR r IN
    SELECT e.user_id, wu.email, e.current_streak, e.streak_start_date
    FROM revit_user_streaks_effective e
    JOIN ws_users wu ON wu.id = e.user_id AND wu.is_active = true
    WHERE e.streak_start_date IS NOT NULL AND e.current_streak >= 7
      AND NOT EXISTS (SELECT 1 FROM gamification_event_logs g
        WHERE g.user_id=e.user_id AND g.event_type='revit_streak_7_bonus' AND g.event_date >= e.streak_start_date)
  LOOP
    PERFORM process_gamification_event(r.user_id, r.email, 'revit_streak_7_bonus','revit', v_yesterday, '{}'::jsonb,
      'revit_streak_7_'||r.user_id||'_'||v_yesterday,
      (SELECT coins FROM gamification_event_types WHERE key='revit_streak_7_bonus' AND is_active), true);
    v_awarded := v_awarded + 1;
  END LOOP;

  -- ===== Revit 30 (награда + сброс цикла, цикл Revit = 30), кроме pending =====
  FOR r IN
    SELECT e.user_id, wu.email, e.current_streak, e.streak_start_date
    FROM revit_user_streaks_effective e
    JOIN ws_users wu ON wu.id = e.user_id AND wu.is_active = true
    WHERE e.streak_start_date IS NOT NULL AND e.current_streak >= 30
      AND (SELECT pending_reset_date FROM revit_user_streaks s WHERE s.user_id=e.user_id) IS NULL
      AND NOT EXISTS (SELECT 1 FROM gamification_event_logs g
        WHERE g.user_id=e.user_id AND g.event_type='revit_streak_30_bonus' AND g.event_date >= e.streak_start_date)
  LOOP
    SELECT completed_cycles INTO v_cycles FROM revit_user_streaks WHERE user_id=r.user_id;
    PERFORM process_gamification_event(r.user_id, r.email, 'revit_streak_30_bonus','revit', v_yesterday,
      jsonb_build_object('completed_cycles', v_cycles+1),
      'revit_streak_30_'||r.user_id||'_'||v_yesterday,
      (SELECT coins FROM gamification_event_types WHERE key='revit_streak_30_bonus' AND is_active), true);
    UPDATE revit_user_streaks SET current_streak=0, streak_start_date=null, completed_cycles=completed_cycles+1,
      pending_reset_date=null, pending_reset_expires_at=null WHERE user_id=r.user_id;
    v_awarded := v_awarded + 1; v_reset := v_reset + 1;
  END LOOP;

  RETURN jsonb_build_object('yesterday', v_yesterday, 'awarded', v_awarded, 'streaks_reset', v_reset);
END $function$;
```

### 2. VPS: `gamification-vps-scripts/src/scripts/catch-up-streak-milestones.ts` (новый)

```ts
import { supabase } from '../lib/supabase.js'
import { createLogger } from '../lib/logger.js'
import type { ScriptResult } from '../lib/types.js'

const log = createLogger('catch-up-streak-milestones')

export async function catchUpStreakMilestones(): Promise<ScriptResult> {
  const { data, error } = await supabase.rpc('fn_catch_up_streak_milestones')
  if (error) {
    log.error(error.message)
    return { success: false, stats: { errors: [error.message] } }
  }
  log.info(`Catch-up: ${JSON.stringify(data)}`)
  return { success: true, stats: data as Record<string, unknown> }
}

const isMain = process.argv[1]?.includes('catch-up-streak-milestones')
if (isMain) {
  catchUpStreakMilestones().then((r) => { if (!r.success) process.exit(1) })
}
```

## Анализ корректности

1. **Будни, порог пересечён в этот день:** compute уже выдал бонус (зелёная ветка). Catch-up идёт после → app-проверка «уже выдан в цикле» + совпадающий idempotency-ключ → **дубля нет.**
2. **Выходные, порог пересечён:** compute пропущены → catch-up единственный выдаёт. ✓
3. **Revit-30 / WS-90 обязаны сбрасывать ВНУТРИ catch-up:** иначе compute на след. рабочий день увидит «бонус уже есть» и **не войдёт в ветку сброса** (сброс у них внутри `if (бонуса нет)`) → цикл не завершится. Поэтому сброс делает сам catch-up. ✓
4. **Порядок:** WS 7/30 до WS 90; Revit 7 до Revit 30 — чтобы сброс (обнуление `streak_start_date`) не «съел» меньший ещё не выданный порог. ✓
5. **Pending:** пользователей в активном pending при сбросе пропускаем — разрулит pending-логика compute. Milestone придёт чуть позже. ✓
6. **+1-триггер WS:** event_date = `v_yesterday`, триггер сдвинет +1 — как у compute-gamification. Консистентно. ✓
7. **Идемпотентность:** ключ `<type>_<uid>_<yesterday>` совпадает с ключом compute в будни → доп. защита `ON CONFLICT`. Основная защита — app-проверка. ✓

## Проверка после ночного прогона

Опорная дата: `fn_minsk_today() - 1` — обработанный день. Стрик-бонусы этой ночи: `event_date >= fn_minsk_today() - 1` (revit — вчера, ws +1 → сегодня).

### Общее (оба сценария)

**A. Прогон был:**
```sql
select max(created_at) as last_event, (select max(snapshot_date) from ach_ranking_snapshots) as last_snap
from gamification_event_logs;
```

**B. Дублей milestone НЕТ — ожидаем 0 строк (обе):**
```sql
select e.user_id, e.event_type, count(*) from gamification_event_logs e
join ws_user_streaks_effective s on s.user_id=e.user_id
where e.event_type in ('ws_streak_7','ws_streak_30','ws_streak_90')
  and s.streak_start_date is not null and e.event_date >= s.streak_start_date
group by e.user_id, e.event_type having count(*) > 1;

select e.user_id, e.event_type, count(*) from gamification_event_logs e
join revit_user_streaks_effective s on s.user_id=e.user_id
where e.event_type in ('revit_streak_7_bonus','revit_streak_30_bonus')
  and s.streak_start_date is not null and e.event_date >= s.streak_start_date
group by e.user_id, e.event_type having count(*) > 1;
```

**C. «Пропущенных» не осталось (кроме pending) — ожидаем ~0:**
```sql
select 'ws30' as k, count(*) from ws_user_streaks_effective e
  where e.streak_start_date is not null and e.current_streak >= 30
    and (select pending_reset_date from ws_user_streaks s where s.user_id=e.user_id) is null
    and not exists (select 1 from gamification_event_logs g where g.user_id=e.user_id and g.event_type='ws_streak_30' and g.event_date >= e.streak_start_date)
union all
select 'revit30', count(*) from revit_user_streaks_effective e
  where e.streak_start_date is not null and e.current_streak >= 30
    and (select pending_reset_date from revit_user_streaks s where s.user_id=e.user_id) is null
    and not exists (select 1 from gamification_event_logs g where g.user_id=e.user_id and g.event_type='revit_streak_30_bonus' and g.event_date >= e.streak_start_date);
```

### Будний день (доп.)

Цель — catch-up **ничего не задублировал**. Ключевое — проверка B = 0. Плюс что бонусы ночи вообще создавались:
```sql
select event_type, count(*), sum(t.coins)
from gamification_event_logs e join gamification_transactions t on t.event_id=e.id
where e.event_type in ('ws_streak_7','ws_streak_30','ws_streak_90','revit_streak_7_bonus','revit_streak_30_bonus')
  and e.event_date >= fn_minsk_today() - 1
group by event_type;
```

### Выходной день (доп.)

Цель — бонусы **теперь приходят** (раньше в Сб/Вс было 0), а green/red по-прежнему НЕ считаются.
```sql
-- бонусы этой (выходной) ночи — ожидаем строки, если кто-то пересёк порог
select event_type, count(*), sum(t.coins)
from gamification_event_logs e join gamification_transactions t on t.event_id=e.id
where e.event_type in ('ws_streak_7','ws_streak_30','ws_streak_90','revit_streak_7_bonus','revit_streak_30_bonus')
  and e.event_date >= fn_minsk_today() - 1
group by event_type;

-- Revit-30/WS-90 в выходной: бонус + сброс (у сброшенных current_streak=0, streak_start_date=null)
select 'revit reset today' as k, count(*) from revit_user_streaks
  where current_streak=0 and streak_start_date is null and completed_cycles >= 1;

-- green/red в выходной по-прежнему НЕ пишутся (правильно) — ожидаем 0
select count(*) as ws_statuses_weekend from ws_daily_statuses where date = fn_minsk_today() - 1;
```
